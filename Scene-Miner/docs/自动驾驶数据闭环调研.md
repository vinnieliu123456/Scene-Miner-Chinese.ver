# 自动驾驶数据闭环行业调研

## 一、什么是自动驾驶数据闭环
### 定义
自动驾驶数据闭环指**道路采集 → 数据筛选 → 数据标注 → 模型训练 → 仿真/实车验证 → 新版本车辆上路采集新数据**的完整循环流程，持续迭代优化感知、预测、规划控制算法，是自动驾驶算法迭代最核心的工程体系。

简单来讲：车在路上遇到难题 → 收集对应的路况视频 → 训练AI学会应对该场景 → 更新软件之后再次上路测试。

## 二、完整闭环各环节详解
### 1. 路测数据采集
测试车辆搭载前视、侧视、后视摄像头、激光雷达、毫米波雷达、GPS‑IMU等传感器，行车途中不间断录制图像、点云、车辆行驶参数。
- 每天车队能够产出TB级别海量录像；
- 绝大多数路况都是平稳直行、通畅路面等常规场景，对算法提升几乎没有收益；
- 真正具备训练价值的为**长尾困难场景**：鬼探头、非机动车横穿马路、雨天逆光、大型车辆遮挡、路面杂物、施工路段等。

### 2. 困难样本筛选（本项目Scene‑Miner所处环节）
传统筛选方式分为两种，均存在明显短板：
1. **触发式采集**：依靠车辆急刹、人工接管、感知置信度暴跌等系统事件触发保存视频；很多潜在危险并不会触发系统告警，隐患样本直接流失。
2. **人工翻阅录像**：数据工程师逐条浏览海量视频，人工找出困难案例，人力成本极高、效率低下。

> 行业痛点也就是我这款Scene‑Miner工具的解决目标：依靠多模态视觉大模型自动检索长尾危险路况，减少人工成本，捕获隐性风险场景。

### 3. 数据标注
筛选完成之后，标注员对图像、雷达点云中行人、电动车、障碍物、车道线等目标进行框选、属性标记。
标注完成的数据集作为训练素材供给算法团队。

### 4. 模型训练
工程师使用标注数据集训练感知模型、障碍物检测模型。针对长尾场景专门做困难样本增强，改善算法在少见路况当中的识别缺陷。

### 5. 仿真测试 + 实车路测
1. 先在仿真平台批量复现危险场景，检验新版模型表现；
2. 合格之后将模型部署至实车；
3. 再次上路行驶，遇到全新的未知困难场景，开启新一轮闭环。

## 三、当前行业现存痛点
1. **有效样本占比极低**：日常行车95%以上都是普通路况，困难长尾场景十分稀缺；
2. 触发式采样存在盲区，大量具备价值的隐患片段无法被系统捕捉；
3. 人工筛查视频工作量繁重，人力成本高昂；
4. 视频体量庞大，如果全部送入大模型识别，会产生巨额算力、Token开销；
5. 困难场景分布不确定，很难定向搜寻特定类型路况（例如下雨天公交车遮挡行人）。

## 四、市面上现存样本筛选方案优缺点
|方案|优势|缺点|
|----|------|-----|
|系统事件触发采集|零算力消耗、技术成熟|隐性风险场景遗漏严重|
|人工回看录像|筛选结果精准|效率很低、人力成本高|
|通用视觉大模型全量解析视频|检索能力强大|海量视频消耗巨额算力Token，落地成本太高|

## 五、Scene‑Miner产品对应的解决方案调研结论
基于行业痛点，本AI工具设计多层级的成本可控架构：
1. 前置结构化参数粗筛，过滤平稳无风险录像；
2. 视频自适应抽帧，减少送入大模型的画面数量；
3. 向量数据库预编码，文字检索阶段不用调用重型多模态大模型；
4. 采用按需推理，用户打开预览弹窗之后才启动深度AI风险解析。

兼顾语义检索长尾路况的能力，同时管控算力开销，可以低成本嵌入自动驾驶的数据闭环流程，帮助算法团队快速补齐稀缺困难样本。

## 六、行业发展方向
1. AI自动筛选、自动标注降低人力成本；
2. 针对各类极端长尾场景搭建场景库；
3. 闭环流程自动化，减少数据工程师重复劳动；
4. 优化多模态大模型推理成本，大规模用于路测视频分析。
